🧾员工问政策

人事政策问答：规则 + RAG + 转人工

员工问人事政策：问题先过人工闸和规则闸，能查表的直接给答案和条款原文，不调模型；其余走 RAG（混合检索 + 重排 + 引用和数字校验），答不准就建工单转人工，工单附上相关条款。每条回答都能评价，Bad 进归因、修复、回归的闭环；HR 工作台看人工介入率和自然通过率。登录演示账户后，按档案里的用工地、参保地和所属公司算出具体天数和金额。演示资料是两份公开的员工手册。

FLOW · 一个问题怎么走

一个问题怎么走

先看要不要交给人，再看能不能查表，最后才交给模型。

① 人工闸

想找人的先找人

  • 只看关键词，不调模型：明说要人工、敏感事项（辞退、赔偿）、查个人数据，直接建工单
  • 「被辞退能赔多少」就算查得到条款也不该让机器答，所以人工闸排第一
  • 身份证、手机号、银行卡在发给模型之前就遮掉，记录和工单里也只存遮过的
② 规则闸

能查表的不交给模型

  • 年假、丧假这类查表题，命中规则直接给答案和条款原文，0 token
  • 缺条件就追问，给按钮选：年假按累计工龄查，先问工龄几年
  • 构建时规则表的每个数字都要在条款原文里找到，对不上就构建失败；规则宁可少命中，漏了只是多走一遍 RAG
③ RAG

校验过了才展示

  • bge-m3 向量 + BM25 混合检索，bge-reranker 重排，DeepSeek 生成，回答带 [1][2] 引用和条款页码
  • 重排分高的直接答；中间的照答，但提示找 HR 核实、给一键转人工；没过门槛就建工单
  • 回答里的天数、金额要在所引条款里找得到才展示，问题里的数字不算，防「婚假是 10 天对吧」这种诱导
FEATURES · 它能做什么

它能做什么

按用到的场景分成几类。

按档案匹配

同一个问题，换个人答案就变

  • 登录演示账户，档案里有所属公司、用工地、参保地、累计工龄、工资，能在页面上改
  • 婚假、产假、育儿假按用工地，生育津贴按参保地，两地不一致就提示并给转人工
  • 年假、加班费、病假工资按所属公司的制度，代入档案里的工资算出具体数
HR 工作台

答不准的交人，答错的变回归题

  • 工单带问题、身份、转人工原因、路由轨迹和 3 条相关条款；HR 回复草稿就用这几条起草，改完才能发
  • 每条回答都能打 Good / OK / Bad；Bad 进队列，人工归因 → 修复 → 一键加入回归集 → 跑评测，不自动改答案
  • 看板看人工介入率（拆成四类）和自然通过率，分子分母都摆出来
评测

门槛来自评测，不靠感觉

  • 30 道自己出的题，对照手册原文：20 道用来定门槛，10 道留出不参与调
  • 路由全对，规则误命中 0、该转人工却答了 0、错答 0
  • 重排门槛取 0.1：该答的题最低 0.377，该转人工的最高 0.049，落在中间的空档里
